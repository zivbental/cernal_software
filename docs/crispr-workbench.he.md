# מהמסמך שלך למודל CRISPR שאפשר להריץ

בניתי עבורך גרסת מחקר עובדת בתוך עותק של CERNAL. היא מתרגמת את החלקים המוגדרים במסמך לקוד, משתמשת בחישובי ViennaRNA אמיתיים, ומוציאה דירוג ומידע על מועמדים שנפסלו. תיקיית הצוות המקורית לא שונתה.

השלב שהושלם הוא **מנוע מחקר שניתן להריץ ולבדוק**. עדיין אין כאן מודל ביולוגי מכויל או חיבור למסך הרצת הניתוח באתר. המשקלים, הספים וכללי החיפוש שנבחרו כבר מוגדרים. נותר לספק קלטים ביולוגיים ותנאי הרצה; אין צורך לשנות את פונקציות המטרה לשם כך.

## להתחיל מהדוגמה

פתח Terminal והדבק:

```bash
cd /path/to/cernal_software
.venv/bin/python tools/run_crispr.py examples/crispr/demo.json --output var/crispr-demo
```

בסביבה הזאת הותקנה סביבת Python מקומית לצורך הבדיקה. במחשב אחר, לאחר התקנת `uv`, מריצים משורש הפרויקט:

```bash
uv sync --extra dev
uv run python tools/run_crispr.py examples/crispr/demo.json --output var/crispr-demo
```

הדוגמה מכילה רצפים מלאכותיים, scaffold צעצוע וציוני קלט לצורך בדיקת תוכנה; הספים וכל המשקלים הם אלה שנבחרו למודל. היא אינה מפעילה את ה־scaffold שלך ואינה מספקת ראיה לפעילות ביולוגית. אין לפרש מעבר של סף בדוגמה ככיול ניסויי.

שני קבצים נוצרים:

- `var/crispr-demo/result.json`: הקלט המלא, גרסת ViennaRNA, הנחות המודל, כל הזוגות והמועמדים הזוכים, מדגם פרטי בדיקה וספירת סיבות הפסילה.
- `var/crispr-demo/ranked.csv`: המועמדים שעברו את התנאים, מדורגים לפי Φ. אם אף מועמד לא עובר, מתקבל קובץ עם כותרות ומצב `no_feasible_candidates`; זו תוצאה תקינה.

`JSON` הוא קובץ טקסט של הגדרות ונתונים. אפשר לערוך אותו בעורך קוד בלי לשנות את האלגוריתם. `CSV` הוא טבלה שאפשר לפתוח גם ב־Excel.

## איך המסמך הופך לקוד

במקום לתרגם את כל המסמך לפונקציה אחת, מחלקים אותו לשלוש שכבות: יצירת מועמדים, מדידת התכונות שלהם, והחלטה מי עובר ומי מדורג גבוה.

| מהמסמך | מה הקוד עושה | איפה בעותק CERNAL |
|---|---|---|
| D ואתרי PAM | סורק NGG בשני הגדילים, עם spacer באורך 20 וגבולות חלון מפורשים | `src/engine/gates/crispr.py` — `scan_spacers` |
| חלונות T בתעתיקים | סורק לפי אורכי התבניות והצעד שנבחרו | `src/engine/stages/switches.py` — `run_endogenous_crispr` |
| g = BT·B·E′·loop·E·S·C | בונה וריאנטים של ה־guide ושומר כל רכיב בנפרד | `CrisprGate.generate_designs` |
| A_OFF ו־A_ON | מחשב את ההסתברות שכל 20 בסיסי ה־spacer חופשיים ביחד | `src/engine/gates/tools/folding.py` |
| d_OFF ו־d_ON | מחשב סטייה ממבנה scaffold נתון, מנורמלת למספר בסיסיו | `FoldEngine.region_defect` |
| ΔG_bind | הפרש אנרגיות חופשיות של ensembles מחוברים ומונומרים | `FoldEngine.binding_free_energy` |
| F ולאחריו J | מפעיל תנאי סף ואז מחשב את הציון הפנימי | `src/engine/scoring/crispr.py` |
| G ולאחריו Φ | מסנן סיכון off-target ומדרג את הזוגות | אותו מודול ניקוד + שלב switches |
| הרצת התהליך | יוצר כלי קיפול אחד ומעביר אותו לשלבים | `src/engine/pipeline.py` |
| קלט ופלט | קורא JSON, מריץ וכותב JSON ו־CSV | `tools/run_crispr.py` |

כך נשמרת ארכיטקטורת הצוות: אין Django במנוע המדעי, ורק כלי הקיפול הקיים פונה לספריית RNA. ציוני J ו־Φ מחושבים בנפרד מהפרופיל הכללי `DEFAULT_V1`; אין כרגע בסיס לכיול משותף עם משפחות שערים אחרות.

## הספים שנבחרו

הספים מרוכזים ב־`src/engine/domain.py`, במחלקה `CrisprObjective`, תחת ההערה `Selected thresholds`:

- `tau_off = 0.05`: נגישות OFF לכל היותר 0.05.
- `tau_on = 0.50`: נגישות ON לפחות 0.50.
- `epsilon = 0.10`: סטיית scaffold קטנה מ־0.10 בשני המצבים.

הדוגמאות יורשות את הערכים האלה מאותו מקום. ניתן להגדיר ערך מפורש בשדה המתאים בתוך `objective` בקלט כדי להשתמש בו בהרצה מסוימת. הפלט שומר את הפרמטרים ששימשו בפועל ב־`objective_parameters`.

## קובץ הקלט שלך

פתח את `cernal_software/examples/crispr/your_model.template.json`.

רצף ה־scaffold ומבנה הייחוס שמסרת כבר נמצאים בו, באורך 80 עמדות. הקוד ממיר T ל־U לצורך קיפול RNA. שאר שדות המחקר החסרים מסומנים `null`, ולכן הרצה שלהם תעצור עם הסבר ולא תמציא נתונים.

| שדה | מה להזין |
|---|---|
| `scaffold_reference` | מבנה הייחוס הפונקציונלי של 80 בסיסי ה־scaffold בפורמט dot-bracket: נקודה לבסיס לא מזווג וסוגריים לזוג בסיסים |
| `target_dna` | מקטע DNA של אזור המטרה, באותיות A/C/G/T |
| `activation_window` | תחילת וסוף חלון ה־spacer בתוך אותו מקטע, באינדקסים שמתחילים ב־0; הסוף אינו כלול |
| `transcripts` | מילון של מזהי תעתיקים והרצפים שלהם |
| `templates` | 30 תבניות: עשרת ערכי `loop_length` מ־14 עד 32 בקפיצות 2, כפול שלושת אורכי BT; בכל תבנית מוגדר extension באורך 10; רצף הלולאה נגזר אוטומטית מהטריגר |
| `host`, `temperature_c` | `human` או `yeast`, וטמפרטורת החישוב לפי השאלה המחקרית |
| `objective` | המשקלים והספים של המסמך ונוסחת Q_S המתוקנת; λ מחושב אוטומטית ואינו שדה קלט |
| `spacer_metrics` | ציוני on-target ו־off-target חיצוניים, עם אותה הגדרת גנום וכיוון ציון |
| `trigger_metrics` | Q_T לכל חלון, מהשלב שבוחר טריגרים; אין חישוב חדש של Q_T במימוש הזה |
| `score_source`, `calibration_source` | מקור הציונים והכיול, כדי שאפשר יהיה לשחזר ולהבין תוצאה |

מבנה מקשי `spacer_metrics` הוא `start:end:strand`, למשל `0:20:+`. מבנה מקשי `trigger_metrics` הוא `transcript_id:start:length`, למשל `toy:0:54`. הציונים החיצוניים נדרשים בטווח 0–1, וסיכון off-target גבוה הוא גרוע. שדה `accessibility` נפרד יכול להיכלל במדדי הטריגר אם חושב במעלה הזרם; הוא אינו זהה אוטומטית ל־Q_T.

אל תעתיק את ציוני הדוגמה אל ההרצה המחקרית. סריקת PAM מוצאת אתרים אפשריים; היא אינה מחשבת יעילות הפעלה או ייחודיות בכל הגנום.

## החלטות מתמטיות שחשוב להבין

**נגישות של כל ה־spacer.** ממוצע ההסתברויות של בסיסים בודדים אינו ההסתברות שכל ה־20 חופשיים יחד, וגם מכפלתן מניחה עצמאות שאינה מובטחת. המימוש משתמש ב־`Z_constrained / Z`: חישוב נוסף שבו כל בסיסי ה־spacer מוכרחים להיות בלתי מזווגים.

**הגדרת OFF ו־ON.** OFF הוא אנסמבל המבנים של g לבדו. ON הוא אנסמבל המבנים המחוברים של קומפלקס gT. בשניהם A הוא יחס פונקציות החלוקה עם ובלי האילוץ שכל 20 בסיסי הספייסר פנויים. d_ON מחושב באותו אנסמבל מחובר. קישור לטריגר אינו כופה פתיחת ספייסר או תבנית זיווג מסוימת. זו הסתברות מותנית בקיום קומפלקס, ולא חישוב של שיעור הקשירה במבחנה; אין צורך בריכוזים ואין שדה bound_fraction. שדות הריכוז הישנים נדחים עם הודעת מעבר מפורשת. מזהה המודל הוא off-g-on-connected-gT-v1. אנרגיית הקישור נותרת G(gT)−G(g)−G(T), ומחושבת בכלי המשותף. הומודימרים, אוליגומרים, חלבונים, קישור DNA וקינטיקה אינם כלולים. הטריגר מחושב כחלון מבודד; ציון Q_T מסופק מבחוץ.

**פונקציית המטרה החיצונית המתוקנת.** Q_S = v_on*eta_on + v_off*(1-eta_off). זו הנוסחה היחידה; אין עוד בחירה ב־spacer_score_mode. Q_pair = W_S*Q_S + W_T*Q_T, והציון הוא Phi = Q_pair*max(0,J_best). J_best המקורי נשמר ללא שינוי, ולצדו j_positive. זוג שעבר את הספים אך J_best שלו אינו חיובי מקבל Phi=0, מדורג בתחתית ונשמר ב־pairs עם selectable=false. הוא אינו נבחר ל־top_candidates או ל־ranked.csv. אם כל הזוגות הכשירים כאלה, הסטטוס הוא no_positive_switch_candidates. זוג שנכשל בסף עדיין נפסל ואינו מקבל ציון דירוג. המשקלים החיצוניים שנבחרו הם v_on=0.4, v_off=0.6, W_S=0.6 ו־W_T=0.4. סף הסיכון הגנומי הוא o_max=0.2: שוויון עובר, וערך גדול ממנו נפסל לפני הקיפול. eta_on, eta_off ו־Q_T הם קלטים מנורמלים ל־0–1 מהשלב הקודם בפייפליין, ומשמשים כפי שסופקו. אין חישוב מחדש או נרמול מחדש במסלול הקריספר.

**הלולאה והטריגר.** הלולאה נגזרת מהטריגר כדי להשתתף בקישור אליו. במימוש הנוכחי אזור הקישור המתוכנן הוא הרצף הרציף BT·B·E′·Loop. לכן אורך החלון הוא `BT + 20 + 10 + L`: בין 54 ל־82 נוקלאוטידים. BT נבחן באורכים 10, 15 ו־20; L נבחן מ־14 עד 32 בקפיצות של 2. אלה 30 שילובי אורכים ו־25 אורכי חלון שונים. לכל שילוב נשמרת החלוקה שלו גם אם רצף ה־guide זהה לזה של שילוב אחר.

**רצף הלולאה.** שני הרצפים נכתבים בכיוון 5′ ל־3′, ולכן הלולאה היא המשלים ההפוך של L הבסיסים הראשונים בחלון הטריגר. אין להזין `template.loop` בנפרד. הפונקציה המשותפת `engine.sequences.reverse_complement` משמשת לבנייתו. זו הגדרת רצף מתוכנן; עצם ההשלמה אינה מוכיחה פתיחה קלה או מהירה יותר. צריך לבדוק את המדידות ולתקף ניסויית, והמודל הנוכחי אינו מחשב קינטיקה.

**האזור החוסם B.** אורכו קבוע — 20 בסיסים — ואינו משתנה לחיפוש. ההחלטה קובעת את האורך בלבד; היא אינה מחייבת השלמה מלאה ל-spacer. רצף B נשאר משתנה בתכנון, כפי שמתואר במסמך.

**הזוג E ו־E′.** אושרה השלמה מלאה ובאורך זהה: `E′ = reverse_complement(E)`, כאשר שני הרצפים נכתבים בכיוון 5′ ל־3′. אלה אינם שני רצפים בלתי תלויים לחיפוש. המימוש משתמש בפונקציה המשותפת `engine.sequences.reverse_complement`. אורכו של כל אחד אושר כקבוע: 10 נוקלאוטידים. האורך אינו משתנה לחיפוש, והקוד דוחה תבנית שבה `extension_length` שונה מ־10.

**סריקה מלאה של שתי אפשרויות בכל עמדה.** לכל עמדה ב־B מוצעים הבסיס המשלים לספייסר והבסיס המשלים למקטע המתאים בטריגר. כשהם זהים נשמרת אפשרות אחת; כשהם שונים נבדקות שתיהן. אם יש m עמדות שונות, נבדקים בדיוק `2**m` רצפים ייחודיים לכל תבנית, עד `2**20`. אין סף של 8 התאמות, אין דגימה ואין הגבלה למספר החלפות. המועמדים נוצרים בהדרגה. זהו חיפוש מלא במרחב שאושר, ולא בכל ארבע האפשרויות בכל עמדה. פרטי המבנה כוללים מספר מועמדים, אינדקס ועמדות משתנות.

**זיכרון ופלט בחיפושים גדולים.** `guide_audit_limit` קובע כמה רשומות אבחון יישמרו בפלט (ברירת מחדל 1000; אפשר 0). הוא אינו מגביל את החיפוש או את הדירוג: כל המועמדים נבדקים, הזוכה לכל זוג נשמר, ובפלט מדווחים מספר הבדיקות, מספר רשומות האבחון שהושמטו וספירת סיבות הפסילה. מטמון חישובי האנרגיה המוגבלים חסום ל־4096 רשומות. המדדים מחושבים בשלבים: A_OFF, אחריו d_OFF, אחריו A_ON ולבסוף d_ON. כישלון בסף עוצר את החישוב עבור המועמד. מדדים שלא חושבו נשמרים כ־null, ונרשמת סיבת הפסילה הראשונה בלבד; ספירת הסיבות מתייחסת לסיבות העצירה, ולא לכל הספים שהמועמד עשוי להיכשל בהם. J מחושב רק למועמדים שעברו את כל הספים.

**מבנה ה־guide.** סדר הרכיבים אושר על ידך לפי איור עמוד 3: ‎5′–BT–B–E′–Loop–E–S–C–3′. הנוסחה בעמוד 2 מציגה סדר שונה ואינה הקובעת. רצפי ה-spacer וה-scaffold נשמרים בכיוון 5′ ל-3′ שסופק, וכל רכיב מקבל גבולות מפורשים. מבנה הייחוס של ה-scaffold שסיפקת הוזן לקובץ הקלט, ונבדק שהוא באורך 80 עמדות עם סוגריים מאוזנים. חיזוי MFE של ה־scaffold לבדו יכול להיות כלי בדיקה, אך אינו מוכיח את המבנה הנדרש לקשירת dCas9.

**משקלים פנימיים ו־λ.** נבחרו w_on=0.4, w_off=0.6 ו־w_energy=w_accessibility=0.5. הערכים נמצאים ב־objective בקובצי הקלט. λ מחושב מכנית בכל הרצה כיחס ממוצעי |J_E| ו־|J_A| על כל המועמדים שעברו את ארבעת הספים, מכל הזוגות שעברו בדיקות קלט וסינון חיצוני מוקדם. זו אצווה משותפת אחת, ולא כיול נפרד לכל זוג או חישוב רק על הזוכים. המדידות נשמרות בקובץ זמני, λ מחושב מהן, ואז נבחרים זוכי J ומחושב Φ ללא קיפול נוסף. מגבלת guide_audit_limit אינה משנה את האצווה. הפלט מתעד את λ ואת מספר המועמדים ב־lambda_calculation. באצווה ריקה אין דירוג ו־λ נשאר null; אם ממוצע |J_A| הוא אפס מתקבלת שגיאה מפורשת. ממוצע |J_E| אפס עם מכנה חיובי נותן λ=0. שדה scale_lambda בקלט נדחה כדי שלא להשתמש בערך ידני. שינוי אצוות המועמדים עשוי לשנות את λ ואת הציונים; להשוואה ישירה בין מועמדים יש לדרג אותם יחד. חישוב λ אינו התאמת משקלים לנתוני ניסוי.

## להעביר לצוות

הקוד נמצא בעותק המלא `cernal_software`. לצד המדריך נמצא גם `crispr_model.patch`, שמכיל רק את השינויים ביחס לתיקייה שסיפקת.

בתיקיית Git של הצוות, לאחר שבודקים שאין שינויים מקומיים שמתנגשים, אפשר לפתוח ענף ולבדוק את ה־patch:

```bash
git switch -c tal/endogenous-crispr-model
git apply --check /path/to/crispr_model.patch
git apply /path/to/crispr_model.patch
uv sync --extra dev
uv run pytest tests/engine -q
```

אם `git apply --check` נכשל, עוצרים ובודקים את ההבדלים; לא דורסים קבצים. לא נוצר commit או PR ולא בוצע push. לחיבור למסך האתר נדרש בהמשך להרחיב את חוזה הקלט של הפרויקט ולחבר את המנוע האמיתי. `CrisprGate.available` נשאר False בממשק, אך ה־workbench רץ משורת הפקודה.

השלב המחקרי הבא הוא להשלים את קובץ הקלט שלך, תחילה עם זוג spacer–trigger ידוע ונתוני ייחוס, ולראות שהמדידות משחזרות התנהגות מוכרת לפני שמגדילים את החיפוש.


**כשל מדידה לעומת פסילה בסף.** מועמד שנכשל בסף מקבל evaluation_status=rejected ו־feasible=false. מועמד שחישובו נכשל מקבל measurement_failed ו־feasible=null; המדדים שכבר חושבו נשמרים, והשאר נשארים null. שגיאות נספרות בנפרד מסיבות פסילה, גם כשהאבחון מקוצר או כבוי. אם יש כשל מדידה כלשהו, הסטטוס הוא measurement_incomplete ו־measurement_complete=false; λ, ציוני J/Φ הסופיים ורשימת ההמלצות אינם מחושבים מאצווה חסרה. רשומות האבחון וסיכומי הזוגות נשמרים. no_feasible_candidates נותר המצב כאשר לא נמצאו מועמדים כשירים וללא כשלי מדידה. קלטים חסרים או לא תקינים עוצרים עם שגיאת קלט לפני הקיפול. סינון off-target תקין מתועד ברשומות הזוגות. הדגל measurement_complete מציין אם המדידות שנדרשו הסתיימו ללא כשל.

**סריקת PAM.** הסריקה קבועה ל־SpCas9 ול־NGG בשני הגדילים: 20 בסיסים לפני PAM, שאינו חלק מהספייסר. activation_window מגביל את כל 20 בסיסי הספייסר בקואורדינטות [start,end). ה־PAM יכול להיות מחוץ לחלון אך חייב להיות בתוך רצף target_dna שסופק. אין זיהוי אוטומטי של סוג Cas/PAM או של אזור בקרה גנומי. בחלון [0,len(target_dna)] נסרק כל הרצף שסופק.

### Research export release boundary (2026-10-11)

The CLI applies the project's `fail_closed_release` to each unique full guide in
retained audits and recommendations. JSON includes `sequence_release` audit
manifests and a `sequence_export` summary. An unapproved guide is null in JSON and
blank in CSV; its numerical diagnostics and rank are retained. Raw input, spacer
and trigger sequence fields, PAMs, and architecture sequence fragments are not
exported. Keep the original input separately; `input_sha256` identifies it.
The current unprovisioned screening stack returns `HOLD_SYSTEM`, so no guide
sequences are released. There is no research bypass. This restriction applies at
the CLI artifact boundary; the internal Python result is unchanged. Use a fresh
output directory for each run, since a failure before writing leaves old files
untouched.
